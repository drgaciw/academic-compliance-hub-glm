# Debugging Guide

This guide covers debugging techniques and tools for Athletic Academics Hub.

## Overview

Debugging is the process of identifying and resolving issues in code. This guide covers:

- Browser debugging
- Server-side debugging
- Database debugging
- Performance debugging
- Debugging tools and techniques

## Browser Debugging

### Chrome DevTools


## Server-Side Debugging

### Next.js Debugging

#### API Route Debugging

```typescript
// apps/main/app/api/users/route.ts
import { NextRequest, NextResponse } from "next/server";

export async function GET(request: NextRequest) {
  // Debug: Log request
  console.log("[API] GET /api/users", {
    url: request.url,
    method: request.method,
    headers: Object.fromEntries(request.headers),
  });

  try {
    const users = await prisma.user.findMany();

    // Debug: Log response
    console.log("[API] Found users:", users.length);

    return NextResponse.json(users);
  } catch (error) {
    // Debug: Log error
    console.error("[API] Error fetching users:", error);

    return NextResponse.json(
      { error: "Failed to fetch users" },
      { status: 500 },
    );
  }
}
```

### Error Handling

```typescript
// packages/api-utils/src/error.ts
export class APIError extends Error {
  constructor(
    public message: string,
    public statusCode: number,
    public code: string,
    public details?: any,
  ) {
    super(message);
    this.name = "APIError";
  }
}

// Usage
try {
  const result = await someOperation();
} catch (error) {
  // Debug: Log full error
  console.error("[Operation] Error:", {
    message: error.message,
    stack: error.stack,
    code: error.code,
  });

  throw new APIError("Operation failed", 500, "OPERATION_FAILED", {
    originalError: error.message,
  });
}
```

#### Query Logging

#### Query Analysis

```typescript

const slowQuery = await prisma.user.findMany({
  where: {
    email: {
      contains: search,
    },

  EXPLAIN ANALYZE SELECT * FROM users WHERE email LIKE ${`%${search}%`}
```

## Common Issues and Solutions

### Issue: Infinite Loop

```typescript
// Bad
useEffect(() => {
  setCount(count + 1); // Triggers effect again
}, [count]);

// Good
useEffect(() => {
  setCount((prev) => prev + 1); // Uses previous value
}, []); // No dependency on count
```

### Issue: Memory Leak

```typescript
// Bad
useEffect(() => {
  const interval = setInterval(() => {
    console.log("tick");
  }, 1000);
  // Missing cleanup!
}, []);

// Good
useEffect(() => {
  const interval = setInterval(() => {
    console.log("tick");
  }, 1000);

  return () => clearInterval(interval); // Cleanup
}, []);
```

### Issue: Race Condition

```typescript
// Bad
let userId;
fetch("/api/user")
  .then((res) => res.json())
  .then((data) => {
    userId = data.id; // May be undefined
  });
console.log(userId); // Race!

// Good
const user = await fetch("/api/user").then((res) => res.json());
console.log(user.id); // Guaranteed
```

### Issue: Stale Closure

```typescript
// Bad
for (let i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(i); // All print 5!
  }, 1000);
}

// Good
for (let i = 0; i < 5; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000 * i); // Stagger
}
```

## Debugging Best Practices

1. **Start with console.log** before using debugger
2. **Use meaningful log messages** with context
3. **Clean up debugging code** before committing
4. **Test hypotheses** one at a time
5. **Document findings** as you debug
6. **Use version control** to bisect issues

<Callout type="info">
  **Pro Tip**: Use `console.trace()` to see call stack without setting
  breakpoints.
</Callout>
