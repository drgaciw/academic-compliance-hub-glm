# Deployment Runbook

This runbook provides step-by-step procedures for deploying Athletic Academics Hub to production.

## Prerequisites

- Access to Vercel dashboard
- Git repository write access
- Project administrator privileges
- Valid environment variables in Vercel

## Pre-Deployment Checklist

Before deploying to production, verify:

- [ ] All tests passing locally
- [ ] Linting completes without errors
- [ ] Type checking passes
- [ ] Database migrations tested
- [ ] Environment variables configured
- [ ] Feature flags set correctly
- [ ] Backwards compatibility verified (if needed)
- [ ] Rollback plan prepared

## Deployment Methods

### Method 1: Git Push (Standard)

**When to use**: Regular deployments, feature releases

```bash
# 1. Ensure on correct branch
git checkout main

# 2. Pull latest changes
git pull origin main

# 3. Merge feature branch
git merge feature/new-feature

# 4. Push to trigger deployment
git push origin main
```

Vercel automatically:

- Runs CI/CD pipeline
- Builds application
- Runs tests
- Deploys to production

### Method 2: Vercel CLI (Manual)

**When to use**: Deploying specific commits, hotfixes

```bash
# 1. Login to Vercel
vercel login

# 2. Deploy specific commit
vercel --prod --message="Hotfix: Critical bug fix"

# 3. Deploy from specific branch
vercel --prod --branch=hotfix-branch
```

### Method 3: Vercel Dashboard (Manual)

**When to use**: Emergency deployments, specific commit deployments

1. **Navigate** to project in Vercel dashboard
2. **Go to** Deployments tab
3. **Find** desired deployment or commit
4. **Click** "..." → "Promote to Production"
5. **Confirm** deployment

## Deployment Pipeline

### Automated Steps

1. **GitHub Action triggers** on push to `main`
2. **CI/CD pipeline runs**:
   ```yaml
   - Checkout code
   - Install dependencies (pnpm install)
   - Run linting (pnpm lint)
   - Run type checking (pnpm type-check)
   - Run tests (pnpm test)
   - Build applications (pnpm build)
   ```
3. **Vercel builds**:
   - Main application
   - Student application
   - Admin application
   - Documentation site
4. **Vercel deploys** to edge network
5. **Health checks** automatically run

### Manual Verification Steps

After deployment completes, verify:

```bash

# 2. Verify main application

# 5. Verify API health
curl https://api.athletic-academics-hub.com/health

# 6. Check Vercel logs
# Vercel dashboard → Deployments → Latest → Logs
```

## Zero-Downtime Deployment

### Canary Deployments

Gradually roll out new version:

```bash
# 1. Deploy to canary environment
git push origin canary

# 2. Gradually increase traffic
# Vercel dashboard → Settings → Edge Network → Traffic Split

# 3. Monitor metrics
# - Error rates
# - Response times
# - User feedback

# 4. Promote to production when stable
```

### Blue-Green Deployment

Run two environments simultaneously:

1. **Deploy** new version to green environment
2. **Test** green environment thoroughly
3. **Switch traffic** from blue to green
4. **Monitor** green environment
5. **Rollback** if issues detected

## Health Checks

### Automated Health Checks

Vercel automatically runs health checks on:

```typescript
// apps/main/app/api/health/route.ts
import { NextResponse } from "next/server";

export async function GET() {
  try {
    // Check database connection
    await prisma.$queryRaw`SELECT 1`;

    // Check external services
    // ...

    return NextResponse.json({
      status: "healthy",
      timestamp: new Date().toISOString(),
      version: process.env.GIT_COMMIT || "unknown",
    });
  } catch (error) {
    return NextResponse.json(
      { status: "unhealthy", error: error.message },
      { status: 503 },
    );
  }
}
```

Monitor in dashboard:

- **Response times**: Should be < 200ms

Configure alerts for:

  "error_rate_threshold": 1.0,  // 1% error rate

## Deployment Troubleshooting

### Build Fails

**Symptoms**: Vercel build fails

**Solutions**:

1. Check build logs in Vercel dashboard
2. Verify dependencies in `package.json`
3. Check TypeScript errors
4. Test locally with `pnpm build`

### Deployment Times Out

**Symptoms**: Vercel deployment hangs

**Solutions**:

1. Increase build timeout in `vercel.json`
2. Optimize build scripts
3. Reduce bundle size
4. Use Turborepo caching

### 504 Gateway Timeout

**Symptoms**: Requests timeout after deployment

**Solutions**:

1. Check serverless function duration
2. Optimize database queries
3. Add caching
4. Increase Vercel timeout limits

### Environment Variables Missing

**Symptoms**: Application errors with missing env vars

**Solutions**:

1. Verify environment variables in Vercel settings
2. Check variable names match code references
3. Restart deployment after adding variables
4. Check variable scope (Production vs Preview)
