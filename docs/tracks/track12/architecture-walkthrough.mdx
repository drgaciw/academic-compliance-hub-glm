## Data Flow Architecture

### Request Flow

```
1. User makes request
   ↓
2. Vercel Edge Network (routing, CDN)
   ↓
3. Next.js App Router (middleware, routing)
   ↓
4. Server Component / API Route
   ↓
5. tRPC Client / Direct Call
   ↓
6. Service Layer (business logic)
   ↓
7. Prisma ORM
   ↓
8. PostgreSQL Database
   ↓
9. Response flows back up
```

### AI Request Flow

```
1. User submits query
   ↓
2. tRPC route receives request
   ↓
3. AI Service processes query
   ↓
4. Vector search (pgvector) for context
   ↓
5. LLM API (OpenAI/Anthropic)
   ↓
6. Response generation
   ↓
7. Streaming to client
   ↓
8. Display in UI
```

### Auth Flow

```
1. User navigates to protected route
   ↓
2. Clerk middleware checks session
   ↓
3. If not authenticated → redirect to login
   ↓
4. User logs in via Clerk
   ↓
5. Clerk generates JWT
   ↓
6. Session stored in cookie
   ↓
7. User redirected to protected route
   ↓
8. Subsequent requests include JWT
   ↓
9. Server validates JWT
   ↓
10. Access granted
```

## Deployment Architecture

### Production Deployment

```
GitHub Repository
    ↓
Push to main
    ↓
GitHub Actions (CI)
    - Lint
    - Type check
    - Tests
    - Build
    ↓
Vercel Deployment
    - Main zone → athletic-academics-hub.com
    - Student zone → student.athletic-academics-hub.com
    - Admin zone → admin.athletic-academics-hub.com
    - Docs zone → docs.athletic-academics-hub.com
    ↓
Vercel Edge Network
    - 50+ locations globally
    - Automatic HTTPS
    - CDN caching
```

### Preview Deployments

```
Pull Request
    ↓
GitHub Actions (CI)
    ↓
Vercel Preview Deployment
    - Auto-generated URL
    - Shared with reviewers
    ↓
Testing & Review
    ↓
Merge to main → Production
```

## Key Design Patterns

### 1. Monorepo Pattern

- Shared code in `packages/`
- App-specific code in `apps/`
- Turborepo for orchestration
- Efficient caching

### 2. Type-Safe API

- tRPC for internal APIs
- End-to-end TypeScript
- Zod for validation
- Auto-generated types

### 3. Server-First Rendering

- Server Components by default
- Client Components when needed
- Optimal performance
- SEO friendly

### 4. Service Layer Pattern

- Business logic in services
- Reusable across apps
- Easy testing
- Clear separation of concerns
