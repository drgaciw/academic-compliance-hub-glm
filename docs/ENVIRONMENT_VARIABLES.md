# Environment Variables Configuration

## Development Environment (.env)

```bash
# Database
DATABASE_URL="postgresql://user:password@localhost:5432/aah_dev"

# Authentication
NEXTAUTH_SECRET=your-dev-nextauth-secret
NEXTAUTH_URL=http://localhost:3000

# OAuth Providers
GOOGLE_CLIENT_ID=your-dev-google-client-id
GOOGLE_CLIENT_SECRET=your-dev-google-client-secret
MICROSOFT_CLIENT_ID=your-dev-microsoft-client-id
MICROSOFT_CLIENT_SECRET=your-dev-microsoft-client-secret

# AI Services
OPENAI_API_KEY=sk-dev-xxx
ANTHROPIC_API_KEY=sk-ant-dev-xxx

# Application
NEXT_PUBLIC_APP_URL=http://localhost:3000
NODE_ENV=development

# CORS
ALLOWED_ORIGINS=http://localhost:3000,http://localhost:3001,http://localhost:3002

# Cookie Domain (for local development, leave undefined)
COOKIE_DOMAIN=
```

## Staging Environment (.env.staging)

```bash
# Database
DATABASE_URL="postgres://user:password@staging-db.vercel-storage.com:5432/verceldb"

# Authentication
NEXTAUTH_SECRET=your-staging-nextauth-secret-change-this
NEXTAUTH_URL=https://staging.aah.vercel.app

# OAuth Providers
GOOGLE_CLIENT_ID=your-staging-google-client-id
GOOGLE_CLIENT_SECRET=your-staging-google-client-secret
MICROSOFT_CLIENT_ID=your-staging-microsoft-client-id
MICROSOFT_CLIENT_SECRET=your-staging-microsoft-client-secret

# AI Services
OPENAI_API_KEY=sk-staging-xxx
ANTHROPIC_API_KEY=sk-ant-staging-xxx

# Application
NEXT_PUBLIC_APP_URL=https://staging.aah.vercel.app
NODE_ENV=production
VERCEL_ENV=preview

# CORS
ALLOWED_ORIGINS=https://staging.aah.vercel.app,https://student-staging.aah.vercel.app,https://admin-staging.aah.vercel.app

# Cookie Domain (for shared auth across zones)
COOKIE_DOMAIN=.vercel.app
```

## Preview Deployment Variables

For each pull request, Vercel automatically creates preview deployments with these settings:

```bash
# Auto-generated by Vercel
VERCEL_URL=aah-git-branch-hash.vercel.app
VERCEL_ENV=preview
NEXT_PUBLIC_VERCEL_ENV=preview

# Use staging environment variables for preview deployments
NEXTAUTH_URL=https://aah-git-branch-hash.vercel.app
NEXT_PUBLIC_APP_URL=https://aah-git-branch-hash.vercel.app

# CORS for preview deployment
ALLOWED_ORIGINS=https://aah-git-branch-hash.vercel.app
```

## Environment-Specific Configuration

### Main App (apps/main)

```bash
# Main app port
PORT=3000

# Main app URL
NEXT_PUBLIC_MAIN_URL=http://localhost:3000

# Other microsite URLs (for cross-zone links)
NEXT_PUBLIC_STUDENT_URL=http://localhost:3001
NEXT_PUBLIC_ADMIN_URL=http://localhost:3002
```

### Student Portal (apps/student)

```bash
# Student portal port
PORT=3001

# Student portal URL
NEXT_PUBLIC_STUDENT_URL=http://localhost:3001

# Other microsite URLs
NEXT_PUBLIC_MAIN_URL=http://localhost:3000
NEXT_PUBLIC_ADMIN_URL=http://localhost:3002
```

### Admin Dashboard (apps/admin)

```bash
# Admin dashboard port
PORT=3002

# Admin dashboard URL
NEXT_PUBLIC_ADMIN_URL=http://localhost:3002

# Other microsite URLs
NEXT_PUBLIC_MAIN_URL=http://localhost:3000
NEXT_PUBLIC_STUDENT_URL=http://localhost:3001
```

## Security Best Practices

1. **Never commit secrets** to version control
2. **Use strong secrets** for `NEXTAUTH_SECRET` (use: `openssl rand -base64 32`)
3. **Rotate secrets regularly** in production
4. **Use environment-specific values** for OAuth callbacks
5. **Set appropriate CORS origins** for each environment
6. **Configure cookie domains correctly** for shared auth
7. **Use Vercel environment variables** for production secrets

## Vercel Environment Variable Setup

1. Go to project settings in Vercel
2. Navigate to Environment Variables
3. Add variables for each environment (Development, Preview, Production)
4. Check "Sensitive" for secrets like API keys
5. Redeploy after adding new variables

## Local Development Setup

1. Copy `.env.example` to `.env`
2. Update values with your local configuration
3. Run `pnpm dev` to start all services
4. Access apps at:
   - Main: http://localhost:3000
   - Student: http://localhost:3001
   - Admin: http://localhost:3002
